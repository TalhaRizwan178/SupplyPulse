# SupplyPulse Recovery Walkthrough

This document scripts the exact failure injection scenario to demonstrate the self-healing capability of the SupplyPulse agent architecture.

## Scenario Setup
- A PO is generated by the Action Planning Agent to procure 1000 units of Lays Masala 70g from the primary supplier for 450,000 PKR.
- The Execution Agent begins executing the actions.

## The Failure Injection
During the execution of Step 2, the system intentionally throws a simulated error:
```json
{
  "step": 2,
  "status": "failed",
  "error": "Supplier rate limit exceeded / Supplier unresponsive"
}
```

## The Recovery Process
1. **Detection**: The Orchestrator Agent intercepts the failed state returned by the Execution Agent.
2. **Escalation**: Instead of stopping the workflow, the Orchestrator passes the failed step details to the Recovery Agent.
3. **Alternative Search**: The Recovery Agent's prompt instructs it to find alternatives for failed procurements. It identifies the secondary supplier.
4. **Constraint Re-Check**: The secondary supplier costs 480,000 PKR. The Recovery Agent verifies this is under the 500,000 PKR budget.
5. **Execution**: The Recovery Agent outputs the new action, which is successfully applied.

## End Result
The workflow continues uninterrupted. The Outcome Agent logs that the intervention saved the 1,000,000 PKR at-risk revenue despite the primary supplier failure, adding only 30,000 PKR in additional cost.
